# Main chat implementation reconciliation

The implementation uses the accepted model menu with effort inside it. Codex profiles come from `model/list` and workspace `config/read`. An invalid configured default remains unavailable and cannot send. Version 1 state migrates atomically to explicit historical Codex ownership without inventing its old model settings.

Antigravity main chat runs in a private empty Git workspace. The original project is supplied as an absolute read-only inspection path in the prompt. Its process and children run under a macOS `sandbox-exec` policy that denies filesystem writes outside private runtime storage and denies reads of `~/.gemini/config`. It also denies access to the bridge runtime and default bridge credentials, except this session's scoped binding, and blocks outbound Unix sockets and other localhost ports. Only the exact scoped bridge TCP port is allowed. A fake-broker regression verifies those boundaries, including symlink access. This avoids project and global MCP discovery. Merely disabling default customizations did not isolate inherited MCP startup in the independent probe. The private-cwd policy passed actual authentication, denied a built-in project write, called both scoped host tools, and did not start the inherited project MCP canary. Other platforms remain unavailable until an equivalent policy is verified.

Antigravity catalogs enumerate actual ACP configuration choices. Each model/effort pair is applied and read back with `session/load`, preserving the exact effective model ID for the worker. A new main session also confirms both values before submitting the user prompt. No suffix parsing maps model families to variants.

Devin's organization MCP allowlist rejects the Herdr server. After the user requested a CLI alternative, an actual isolated ACP probe read an absolute project path, invoked a local helper twice through its built-in command tool, and failed an attempted project write. The implementation uses this local CLI transport with no MCP servers or policy changes. A permission callback approves only the exact current binding, turn operation, and host tool command plus one schema-validated JSON or base64 argument. Shell operators and other commands are rejected. Helper startup disables workspace Bun configuration, environment files, macros, and dependency installation. Both transports call the same durable HostTools handler.

Devin uses private XDG configuration, data, cache, and temporary directories with a private 0600 copy of the existing login credential. Shared Devin configuration, credentials, and customizations remain unreadable to that process; only the canonical installed binary version is exempted. Its session mode is confirmed as `accept-edits`; the OS denies project writes, and the command permission callback admits only the scoped helper. Actual ACP configuration supplies model families and their supported efforts. The advertised `persistOnCreate` extension creates the private session record; after applying options and loading the session, a read-only query reads its exact effective model ID. This avoids guessing variant suffixes. Fusion options remain disabled because they introduce extra agents. The product catalog returned 43 families in a private probe. The [native verification record](main-chat-verification.md) documents completed Devin dispatch, model inheritance, file readback, and result delivery.

The sandbox allows the exact macOS DNS socket `/private/var/run/mDNSResponder`, while other Unix control sockets stay denied. Exact ancestor-directory metadata is readable so Devin's SQLite path resolution works; directory contents and sibling credentials remain denied. The fake-broker regression covers these exceptions together with protected files, a symlink, unrelated localhost access, and a fake Herdr socket.

The user subsequently authorized YOLO defaults for Antigravity and Devin workers. Native launches therefore use `agy --dangerously-skip-permissions` and `devin --permission-mode dangerous --respect-workspace-trust false`. Codex worker policy is unchanged. Main-chat containment remains separate.

Native workers own their interactive CLI until it exits. Stop hooks report results, but the project stays occupied while that CLI remains open. This is deliberate because Devin Stop has no background-quiescence field. Antigravity Stop with `fullyIdle=false` does not report a finished turn. Its `executionNum` repeats across user turns, so the reporter captures the latest transcript `USER_INPUT.step_index` and final text at hook time. The bridge uses that boundary plus session ID for deduplication. A later bridge restart reads private spool files and never relaunches a task.

Codex terminal attachment now precedes the first `turn/start`. Launch checkpoints distinguish an intent from an attempted external effect. Native `hc run` creates a terminal and starts its CLI together; that cannot be described as the same atomic sequence. If attachment acknowledgement is lost, the task remains unknown and is not replayed.

Host tools use one shared handler. Codex carries its authoritative turn ID. ACP tools include a host-issued operation ID and a session-scoped credential. Reusing a committed operation with the same parsed arguments returns the durable receipt; changing arguments conflicts. An inactive run cannot first create a task or explanation.

The official mod commands `open-cli`, `open-model`, `choose-cli:<id>`, `choose-model:<id>`, and `choose-effort:<id>` call the same handlers as the native selectors. They support command-driven verification without claiming native pointer coverage.

Local checks currently cover profile admission and model application, repeated configuration requests, stale revisions, concurrent opens, migration, task terminal ordering, native report identity and session occupancy, and the existing Codex protocol behavior. The [native verification record](main-chat-verification.md) and [protocol verification](../../verification/herdr-chat/README.md) record the completed checks and their limits.

The desktop CLI now runs only under `import.meta.main`. The broad module-import test previously triggered the installer through that unguarded entry point; its child processes now have blocked native commands plus explicit isolated runtime and app directories. The installer honors `HERDR_APP_HOME` when explicitly supplied. Normal installation still uses the native app directory.
