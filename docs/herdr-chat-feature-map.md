# Herdr chat verification map

The project [verify skill](../.agents/skills/verify/SKILL.md) drives the native GPUI workbench. Its [journeys](../.agents/skills/verify/features/README.md) are the maintained user-facing checks. Task dispatch requires a chat action, a new worker in the original sidebar, actual terminal execution, an observed file effect, and a result returned to chat. Native input and official command entry points have separate coverage records.

[Desktop protocol tests](../test/desktop.test.ts) use the [deterministic protocol peer](../test/desktop-fixture.ts). They support checks for deduplication, persistence, explanation validation, approval ownership, result identity, and disconnect behavior. They do not prove native typing, scenario clicks, real Codex execution, or actual terminal approval.

[Profile tests](../test/desktop-profile.test.ts) check configuration revisions, immutable accepted requests, invalid effort rejection, and v1 migration. The [current protocol verification](../verification/herdr-chat/README.md) maps bounded profile, receipt, dispatch, and native session rules to source and runtime fault probes. The [provider design models](../verification/main-chat-providers-design/README.md) remain a historical design record. Neither replaces a real provider journey. The [three-provider native verification](design/main-chat-verification.md) records actual integration runs and known coverage limits. The [native CLI observations](design/native-provider-probes.md) record the separately launched worker probes and their limits.

Store run evidence under `evidence/herdr-chat/<run>/` using the skill's commands. Record each sub-feature as a live pass, failed, blocked, not run, protocol only, or source only. This map describes the proof required. It does not imply every journey has already passed.

The [recorded verification](herdr-chat-verification.md) distinguishes native input, official Herdr commands, protocol tests, and formal checks. Live runs proved chat dispatch, one worker, file effects, returned results, terminal continuation, and original-sidebar working/idle states. Final navigation used the user-requested official Herdr driver. Native sidebar clicks and the send button remain separate unrun checks.

The original Agents sidebar must show dispatched workers and open their terminals. A task tab alone is incomplete proof, even if the remote Codex TUI emits no native status. The transcript requires manual scrolling. Scenario choice is local view state, not a persisted preference. The [workbench guide](herdr-chat.md) describes installation and runtime scope.
