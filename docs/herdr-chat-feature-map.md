# Herdr chat verification map

The project [verify skill](../.agents/skills/verify/SKILL.md) drives the native GPUI workbench. Its [five journeys](../.agents/skills/verify/features/README.md) are the maintained user-facing checks. The task-dispatch journey requires real native input, a new Codex worker, actual terminal execution, an observed file effect, and a result returned to chat.

| User journey | Source ownership | Evidence that proves it |
| --- | --- | --- |
| [Conversation and persistence](../.agents/skills/verify/features/native-conversation.md) | [Native composer and transcript](../herdr/mods/dori-chat/main.js), [conversation lifecycle](../src/desktop/engine.ts), [durable state](../src/desktop/store.ts), [tab installation](../src/desktop/install.ts). | Native Enter and send-button actions, continued answer, reopened transcript, and unchanged message identities. |
| [One task and returned results](../.agents/skills/verify/features/task-dispatch.md) | [Chat tool instructions](../src/desktop/tools.ts), [dispatch and result delivery](../src/desktop/tasks.ts), [real Codex terminal attachment](../src/desktop/herdr.ts), [native status adapter](../src/desktop/terminal.ts). | Before and after task IDs, the original Agents sidebar entry and native click into its terminal, labeled terminal and thread identity, worker command output, file contents, and one matching chat result. |
| [Terminal continuation and approval](../.agents/skills/verify/features/terminal-control.md) | [Worker turn and approval events](../src/desktop/tasks.ts), [remote terminal identity](../src/desktop/herdr.ts), [RPC routing](../src/desktop/engine.ts). | Running, waiting, and finished sidebar states, a second native terminal turn on the same worker, its distinct result in chat, and an actual terminal approval decision when present. |

[Desktop protocol tests](../test/desktop.test.ts) use the [deterministic protocol peer](../test/desktop-fixture.ts). They support checks for deduplication, persistence, explanation validation, approval ownership, result identity, and disconnect behavior. They do not prove native typing, scenario clicks, real Codex execution, or actual terminal approval.

Store run evidence under `evidence/herdr-chat/<run>/` using the skill's commands. Record each sub-feature as a live pass, failed, blocked, not run, protocol only, or source only. This map describes the proof required. It does not imply every journey has already passed.

The [recorded verification](herdr-chat-verification.md) distinguishes native input, official Herdr commands, protocol tests, and formal checks. Live runs proved chat dispatch, one worker, file effects, returned results, terminal continuation, and original-sidebar working/idle states. Final navigation used the user-requested official Herdr driver. Native sidebar clicks and the send button remain separate unrun checks.

The original Agents sidebar must show dispatched workers and open their terminals. A task tab alone is incomplete proof, even if the remote Codex TUI emits no native status. The transcript requires manual scrolling. Scenario choice is local view state, not a persisted preference. The [workbench guide](herdr-chat.md) describes installation and runtime scope.
